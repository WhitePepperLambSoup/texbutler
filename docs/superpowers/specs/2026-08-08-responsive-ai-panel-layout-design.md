# 响应式编辑器工具栏与 AI 对话面板设计

日期：2026-08-08

## 背景

当前应用的外层列布局已经能够在项目树、编辑器、PDF 和 AI 面板之间分配宽度，但各面板内部仍按单行工具栏渲染。真实浏览器复现得到以下结果：

- 默认 `1280 x 800`、无 PDF 时，编辑器标题栏可用宽度为 666px，内容滚动宽度为 1083px。
- 默认 300px AI 面板中，标题栏可用宽度为 297px，内容滚动宽度为 502px。
- AI 标题栏中的建议模式、时间线、项目指南和清空操作整体位于可视范围之外。
- AI 输入框未参与横向伸缩，只占约 155px，发送按钮右侧留下无意义空白。
- 打开建议修改后，独立的 diff 栏和建议列表会把消息区压缩到约 16px。
- PDF 打开后编辑器会合理缩小到 200px，但原有 1083px 工具栏只能显示最左侧少量按钮。

这些问题的根因不是外层面板互相覆盖，而是功能逐步追加到通用 `.panel-header` 后，没有建立适合窄工具面板的响应式信息层级和溢出收纳机制。现有 E2E 仅验证外层矩形不相交，无法发现操作被裁切或聊天区坍缩。

## 目标

1. AI 对话面板在 240px 至 520px 的允许宽度内保持结构稳定，所有功能始终可访问。
2. 普通对话、建议修改、快照时间线和回滚状态共享可预测的纵向布局。
3. 输入框使用完整可用宽度，发送操作位置稳定。
4. 编辑器在 PDF 打开并缩小到最小宽度时，不再让工具栏伸入或隐藏在相邻面板下方。
5. 保留现有会话、token、建议模式、快照、项目指南、diff 应用和回滚行为，不改变 Zustand 状态或 Tauri 命令契约。
6. 用可重复的布局回归测试覆盖当前缺失的内部溢出与可访问性断言。

## 非目标

- 不重构 AI 请求、流式事件、会话持久化或文件绑定逻辑。
- 不改变项目树、PDF 预览、编译面板和底部问题面板的业务行为。
- 不重新设计整个主题系统。
- 不把 AI 面板改为覆盖编辑器或 PDF 的浮动抽屉。

## 方案比较

### 方案 A：紧凑顶栏、更多菜单和统一滚动区（采用）

把高频操作保留在稳定位置，把低频操作收进菜单；消息、diff、建议块和时间线使用同一滚动容器。该方案同时解决横向裁切、纵向挤压和输入区错位，且不改变外层工作区结构。

### 方案 B：所有操作自动换行

实现成本较低，但按钮数量较多时会持续占用聊天高度。中英文文案长度不同，标题栏高度也会大幅波动，无法保证稳定体验。

### 方案 C：AI 覆盖式宽抽屉

能够提供更多水平空间，但会遮住编辑器或 PDF，破坏当前多面板并行工作流，也使频繁查看编译结果变得低效。

## AI 面板结构

### 展开与收起

AI 面板展开时，不再保留独占 44px 高度的空白收起条。收起按钮进入 AI 顶栏右侧。AI 面板收起时，继续显示现有 34px 竖向入口，以保持发现性和已保存的展开状态行为。

`AiRail` 负责展开状态和宽度，向 `AiPanel` 传入 `onCollapse`。`AiPanel` 只负责内部布局，不接管宽度持久化。

### 顶栏

顶栏使用两个稳定行，而不是把所有元素塞进通用单行标题栏：

- 主行：AI 标题、会话选择、新建会话、更多菜单、收起按钮。
- 状态行：当前绑定文件、紧凑 token 摘要、建议模式开关。

会话名称和文件名使用省略显示，并保留完整 `title` 提示。主行中的图标按钮保持固定尺寸，不随文案或状态改变布局。

### 更多菜单

以下低频操作进入更多菜单：

- 重命名当前会话
- 删除当前会话
- 打开快照时间线
- 生成项目指南
- 清空当前消息
- 重置 token 统计

不适用于当前状态的操作使用禁用状态，而不是从菜单中随机消失。菜单支持点击外部和 `Escape` 关闭。

### 对话滚动区

`.ai-body` 成为 AI 面板唯一的主滚动区，并按顺序容纳：

1. 普通消息
2. 待确认 diff 摘要
3. 建议修改块
4. 快照时间线

建议块和时间线不再作为与消息区竞争高度的独立 flex 兄弟元素。打开这些内容时，消息区保持正常高度，用户通过同一个滚动区查看完整上下文。现有自动滚动逻辑继续在消息或待处理 diff 更新后滚动到底部。

### 消息样式

用户消息右对齐，助手和系统消息左对齐，保留当前角色区分。调整间距、最大宽度、代码和 diff 内边距，使 240px 宽面板中长单词、路径和 LaTeX 内容可以换行或在代码区内滚动，不撑大面板。

### 输入区

输入区固定在面板底部，但不覆盖滚动内容：

- textarea 设置 `flex: 1`、`min-width: 0` 和完整可用宽度。
- 发送按钮使用固定方形图标按钮，位于输入区右下侧，并提供文字提示。
- textarea 保留纵向调整能力，但最大高度受面板约束。
- 选区上下文和回滚操作显示为输入框下方的状态项，可换行且不会改变发送按钮位置。
- 保留 Enter 发送、Shift+Enter 换行和 IME 组合输入保护。

## 编辑器工具栏结构

编辑器标题栏只保留：

- 可横向滚动的文件标签
- 保存
- 问 AI
- 更多工具

插图、段落、标题、加粗、公式、符号、表格、翻译、润色、分屏、片段选择和 PDF 定位进入编辑器更多工具菜单。菜单位于编辑器内部，宽度受当前编辑器约束，可换行并在内容过高时滚动。这样即使编辑器缩小到 200px，主要操作和全部次要操作仍然可访问，也不会伸入 PDF 区域。

现有命令处理函数继续复用，不改变插入、翻译、润色、保存或 SyncTeX 行为。

## 图标与可访问性

新增 `lucide-react`，用于发送、更多、收起、新建、保存、AI、历史、指南、清空、重命名和删除等标准动作。图标按钮提供 `title` 和 `aria-label`，并使用稳定的 28px 至 32px 点击区域。现有业务文案继续通过 i18n 获取。

## 状态与数据流

新增状态仅限组件内 UI 状态：

- AI 更多菜单是否打开
- 编辑器更多工具菜单是否打开

会话、消息、token、建议模式、diff、快照和编辑器内容仍由现有 store/API 提供。菜单只是现有操作的入口，不复制或缓存业务数据。

## 错误处理

- token 读取失败时继续隐藏摘要，和当前降级行为一致。
- 快照读取失败时显示空状态，不影响普通对话。
- 项目指南、重命名、删除和清空继续使用现有确认与错误提示。
- 菜单关闭不会取消正在进行的 AI 请求。
- busy 状态继续禁用会产生会话竞态的操作。

## 回归测试

在生产代码修改前新增布局回归测试，并先确认它在当前实现上因以下条件失败：

1. AI 顶栏 `scrollWidth` 不得大于 `clientWidth`。
2. AI 面板和编辑器面板不得产生超出自身边界的工具栏内容。
3. AI 输入框必须占满发送按钮之外的可用宽度，输入行不得留下大块空白。
4. 普通聊天状态下消息区保持可用，并且输入区位于 AI 面板底部以内。
5. 建议修改状态下主滚动区不得坍缩，diff 和建议块应位于该滚动区内。
6. 打开 PDF、编辑器缩小到 200px 时，保存、问 AI 和更多工具仍可见。
7. 更多菜单中的低频操作全部可访问。

真实视口覆盖：

- `960 x 700`
- `1280 x 800`
- `1600 x 900`

状态覆盖：

- 无 PDF 与有 PDF
- 空对话与多轮长对话
- 普通聊天与建议修改
- AI 面板 240px、300px 和 520px 宽度
- liquid、dark 和 light 三种主题的视觉截图
